# 오늘의 생활 이슈 글 작성 지침

매일 밤 클라우드 루틴이 이 지침대로 글 2편을 써서 예약 발행한다. 사람이 다시 확인하지 않고 바로 공개되므로, 사실 확인과 아래 규칙을 지키는 것이 무엇보다 중요하다.

## 1. 발행 일정

- 루틴은 매일 밤(한국 시각 21시 무렵) 실행된다.
- 글 2편을 쓰고 `publishAt`을 **다음 날 00:00**과 **다음 날 05:00**(한국 시각)으로 넣는다.
- 날짜 계산은 반드시 한국 시각(Asia/Seoul) 기준으로 한다. `TZ=Asia/Seoul date`로 확인할 것.
- `date`는 발행일(다음 날)로 넣는다.

## 2. 주제 고르기

그날(한국 시각) 나온 뉴스 중 **독자의 돈과 생활에 직접 영향을 주는 생활·경제 이슈**만 고른다.

다룰 것:
- 금리, 세금, 물가, 공공요금, 부동산 정책, 대출 규제
- 정부 지원금·제도 신설과 변경, 신청 시작·마감
- 건강보험·연금·고용보험 같은 사회보험 변화
- 통신·교통·에너지 요금, 소비자 피해 주의보
- 계절성 생활 정보로 이어지는 공식 발표 (예: 한파 대비 지원, 독감 접종 확대)

다루지 않을 것:
- 연예, 스포츠, 사건·사고, 범죄
- 정치 공방, 선거, 특정 정당·정치인 평가
- 개별 주식·코인 추천, 주가·집값 예측
- 의학적 효능 단정, 확인되지 않은 루머
- 이미 신청이 끝난 지원금 (마감 이후에는 쓰지 않는다)

주제를 고르는 순서:
1. 웹 검색으로 그날 발표된 정부 보도자료(korea.kr 정책브리핑, 각 부처, 한국은행, 국세청, 금융위원회 등)와 주요 경제 뉴스를 훑는다.
2. 후보마다 "이 뉴스로 독자가 무엇을 해야 하나, 무엇이 달라지나"를 한 문장으로 쓸 수 있는지 본다. 쓸 수 없으면 버린다.
3. `content/posts/`의 기존 글 제목과 파일 이름을 확인해 최근 2주 안에 같은 주제를 다룬 글이 있으면 버린다. 기존 글과 관련은 있지만 새 소식이면 써도 되고, 기존 글로 링크한다.
4. 조건에 맞는 이슈가 2개가 안 되면, 억지로 채우지 않는다. 대신 최근 1~2주 안의 생활·경제 이슈 중 아직 다루지 않은 것을 "무엇이 달라지나" 해설로 쓴다.

## 3. 사실 확인 (가장 중요)

- 숫자, 날짜, 금액, 대상 조건은 **1차 출처**(정부·공공기관 보도자료, 법령, 공식 누리집)에서 확인한다.
- 1차 출처를 찾지 못한 내용은 언론 보도 2곳 이상에서 같은 내용이 확인될 때만 쓰고, "○○ 보도에 따르면"처럼 출처를 밝힌다.
- 확인되지 않은 수치는 쓰지 않는다. 블로그 글은 출처로 쓰지 않는다.
- 발표 단계인 정책(국회 통과 전, 시행 전)은 "추진", "발표", "국회 통과 시"처럼 상태를 정확히 적고, 확정된 것처럼 쓰지 않는다.
- 시행일·신청 기간이 있으면 반드시 적는다.

## 4. 글 형식

파일: `content/posts/issue-YYYYMMDD-영문키워드.md` (YYYYMMDD는 발행일, 영문키워드는 소문자와 하이픈)

frontmatter:

```
---
title: 검색하는 사람이 쓰는 말로 된 제목, 핵심 변화가 드러나게
description: 1~2문장 요약. 무엇이 언제부터 어떻게 달라지는지.
category: 생활 이슈
icon: bolt
date: YYYY-MM-DD
publishAt: YYYY-MM-DD 00:00
---
```

`icon`은 주제에 맞게 `won`, `percent`, `home`, `car`, `bolt`, `flame`, `shield`, `receipt`, `calendar`, `phone`, `doc` 중에서 고른다.

본문 구성 (분량은 한글 1,500~2,500자):
1. 첫 문단: 무슨 일이 있었는지, 누구에게 영향이 있는지 2~3문장.
2. `## 무엇이 달라지나`: 바뀌는 내용. 전후 비교가 있으면 표로.
3. `## 나는 해당될까`: 대상 조건.
4. `## 지금 할 일`: 신청 방법, 기한, 확인할 곳. 독자가 바로 할 수 있는 행동.
5. 관련 기존 글이 있으면 본문 중간에 자연스럽게 링크 (`[글 제목](/posts/슬러그/)`). 관련 계산기가 있으면 `{{calc:이름}}` 한 줄 (이름은 `content/calculators/` 파일 이름).
6. `## 정리`: 핵심 3~4줄.
7. `## 참고 자료`: 확인한 1차 출처 링크 1~3개 (`- [기관명: 제목](URL)`).

## 5. 문체 규칙

- 해요체와 합니다체를 섞되 자연스럽게. 문장 길이를 다양하게.
- 굵은 글씨(`**`)는 글 전체에서 10곳 이하.
- 직접 해 본 것처럼 꾸민 경험담("저도 해 봤는데")은 쓰지 않는다.
- "~에 대해 알아보겠습니다", "결론적으로", "다양한", "중요합니다" 같은 기계적인 표현을 반복하지 않는다.
- 뉴스 기사 문장을 그대로 옮기지 않는다. 인용은 한 문장 이내로, 출처를 밝힌다.
- 독자를 불안하게 만드는 낚시성 제목("충격", "큰일 난다")은 쓰지 않는다.

## 6. 그림 (선택)

전후 비교나 일정처럼 그림이 이해를 돕는 경우에만 `content/figures/이름.svg`를 만든다. 기존 그림(예: `content/figures/vat-yearly-schedule.svg`)과 같은 스타일(640px 너비, Pretendard, 흰 배경 카드)을 따른다. 본문에는 `![대체 텍스트](/figures/이름.png "설명")`로 넣는다. 확신이 없으면 그림 없이 표로 충분하다.

## 7. 마무리 절차

1. `npm ci` (처음 한 번) 후 `npm run build`가 오류 없이 끝나는지 확인한다. 빌드 출력에 두 글이 "예약 대기"로 나와야 한다.
2. 새로 만든 글과 그림 파일만 커밋한다. 다른 파일은 고치지 않는다.
3. 커밋 메시지: `오늘의 생활 이슈 YYYY-MM-DD: 첫 글 주제, 둘째 글 주제`
4. `main`에 push한다. 예약 시각이 되면 GitHub Actions가 자동으로 배포한다.
5. 글을 하나도 쓰지 못했다면 커밋하지 말고 이유를 남긴다.
